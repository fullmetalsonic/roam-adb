# RoamADB — 제품 요구사항 기획서

## 1. 문서 상태

- 상태: 승인된 제품 기준, `v0.1.2-spike` 무선 경로 공개 + 휴대형 USB 브리지 계획 승인
- 작성일: 2026-08-24
- 구현 승인: 2026-08-24 받음
- 기준 실기기: Samsung Galaxy Z Fold8, Android 17, One UI 9
- 최소 지원 목표: Samsung Android 16, One UI 8 이상
- 배포 목표: GitHub Public 소스 및 Release APK
- Google Play: 게시하지 않음

## 2. 제품 목표

외부에 들고 나간 Android 휴대폰을 집의 Windows PC에서 표준 ADB 장치처럼 연결하여 Codex, Android Studio, `adb`, `logcat`, APK 설치, 파일 전송, `scrcpy`를 사용할 수 있게 한다.

현재 소프트웨어 경로에서 휴대폰 사용자는 공식 Tailscale과 RoamADB를 사용하며 Termux, Shizuku와 LADB를 각각 설치·설정하지 않는다. 후속 원툴 경로는 단일 Android 앱에서 최초 설정과 연결 ON/OFF를 처리하는 목표를 유지한다.

추가 `portable-usb-bridge` 경로에서는 작은 Linux ADB host를 휴대한다. Fold8은 LTE/5G와 자체 핫스팟을 제공하고 브리지는 USB ADB와 별도 Tailscale node를 담당한다. 이 경로는 Android 무선 디버깅의 Wi-Fi 전제조건을 제거하기 위한 선택 모드이며 기존 무선 경로를 삭제하지 않는다.

## 3. 핵심 사용자 시나리오

### 3.1 현재 무선 경로

1. 사용자가 휴대폰에서 최초 설정을 완료한다.
2. 외부 Wi-Fi와 공식 Tailscale을 준비한다.
3. 앱의 큰 토글 또는 빠른 설정 타일을 눌러 원격 디버깅을 켠다.
4. 앱이 사설망과 무선 ADB relay를 준비한다.
5. 집 PC에서 표준 ADB 또는 Gateway가 휴대폰에 연결한다.
6. Codex 또는 개발 도구가 휴대폰을 진단·디버깅한다.
7. 사용자가 토글을 끄면 원격 접근 통로가 종료된다.

### 3.2 휴대형 USB 브리지 경로

1. 사용자가 Fold8의 LTE/5G, 2.4GHz 핫스팟과 USB 디버깅을 준비한다.
2. 휴대형 브리지에 전원을 공급하고 Fold8 USB에 연결한다.
3. 브리지가 핫스팟, Tailscale과 Fold8 USB `adbd`를 순서대로 확인한다.
4. 집 PC가 Tailscale 제한 SSH 또는 후속 인증 Agent로 브리지에 접속한다.
5. Codex 또는 개발 도구가 브리지의 ADB를 통해 Fold8을 진단한다.
6. 사용자가 브리지 전원 또는 연결을 해제하면 원격 접근이 종료된다.

## 4. 제품 원칙

- 루팅 없이 동작하는 것을 기본 목표로 한다.
- 사용자가 요청할 때만 연결하며 부팅 자동연결은 하지 않는다.
- 외부 공개 ADB 포트 대신 인증된 직접 tunnel 또는 Tailscale 사설망과 Android 기본 ADB 인증을 사용한다.
- 앱이 준비된 상태와 PC가 실제 접속한 상태를 구분한다.
- 실패 시 빈 화면이나 무한 로딩 대신 현재 단계와 해결 방법을 표시한다.
- 회사 데이터, ADB 명령 내용, 화면 내용과 파일 내용을 수집하거나 외부 서버로 보내지 않는다.
- 소스와 APK를 재현 가능하게 공개하고 제3자 라이선스를 명확히 표시한다.

## 6. 기능 요구사항

### FR-001 최초 설정

- 먼저 현재 무선 경로와 휴대형 USB 브리지 경로의 조건·장단점을 표시한다.
- 개발자 옵션과 무선 디버깅 활성화 방법을 단계별로 안내한다.
- Tailscale 모드를 선택한 경우에만 최초 VPN 권한을 Android 시스템 화면에서 사용자가 승인한다.
- 최초 ADB 페어링 코드와 포트를 입력하거나 탐지할 수 있다.
- Tailscale 모드를 선택한 경우 로그인은 외부 브라우저 또는 안전한 시스템 인증 흐름을 사용한다.
- 직접 PC 서버 모드는 PC Helper의 QR·코드와 서버 인증서 지문으로 등록한다.
- 설정 단계별 성공·실패를 검사하고 다음 버튼을 활성화한다.
- USB 브리지 경로에서는 무선 디버깅·무선 페어링을 요구하지 않고 USB 디버깅, 브리지 전원, 2.4GHz 핫스팟, 브리지 Tailscale과 USB RSA 승인 순서로 안내한다.

### FR-002 연결 ON/OFF

- 앱 메인 화면에 큰 ON/OFF 토글을 제공한다.
- 빠른 설정에 토글 가능한 타일을 제공한다.
- 잠금 상태에서 ON 요청 시 잠금 해제를 요구한다.
- 부팅 후 자동으로 켜지지 않는다.
- OFF 시 직접 tunnel 또는 VPN과 원격 ADB 진입점을 종료한다.

### FR-003 연결 상태

- 다음 상태를 서로 구분한다.
  - 설정 필요
  - 꺼짐
  - 시작 중
  - 휴대폰 준비됨
  - PC 연결됨
  - 복구 중
  - 오류
- 각 상태에 현재 작업, 예상 다음 단계와 사용자가 할 행동을 표시한다.

### FR-004 ADB 기능

집 PC에서 표준 ADB를 통해 다음 기능이 가능해야 한다.

- `adb devices`
- `adb shell`
- `adb logcat`
- `adb install` 및 `adb uninstall`
- `adb push` 및 `adb pull`
- 포트 forward/reverse
- Android Studio 장치 연결
- `scrcpy` 화면 보기·입력 제어

### FR-005 PC 연결

- 일반 사용자를 위한 Windows PC Helper를 제공한다.
- 숙련자를 위한 CLI 또는 PowerShell 명령도 제공한다.
- Helper가 표시하는 QR 또는 6자리 일회용 코드로 집 PC를 휴대폰에 등록한다.
- 휴대폰은 접속 소스의 Tailscale 장치 신원을 확인하고 사용자가 허용한 PC만 relay에 접속시킨다.
- Helper는 ADB 경로, Tailscale 상태, 휴대폰 주소, 연결 결과를 검사한다.
- PC가 꺼져 있어도 휴대폰은 `준비됨` 상태가 될 수 있다.
- PC가 접속하면 휴대폰 화면에 접속 시각과 승인 PC를 표시한다.

### FR-006 허용 PC와 회수

- relay가 허용한 Tailscale PC 신원 또는 앱 자체 PC 등록 정보를 확인할 수 있다.
- 허용 PC를 relay 목록에서 개별 삭제할 수 있다.
- Android 시스템의 ADB RSA 승인 목록은 일반 앱이 자유롭게 열람·수정할 수 있다고 가정하지 않는다.
- Android 자체 ADB 승인 철회가 필요하면 개발자 옵션의 `USB 디버깅 승인 취소` 또는 동등한 시스템 화면으로 안내한다.
- 앱 자체 PC 허용 목록과 로컬 페어링을 각각 초기화할 수 있다.
- 휴대폰 앱에서 즉시 연결을 중지할 수 있다.

### FR-006A 다중 인증

- Tailscale 노드 인증, RoamADB relay 허용 PC와 Android 기본 ADB 페어링·키 승인을 서로 다른 방어 계층으로 사용한다.
- 동일 tailnet의 미등록 장치도 relay가 거부해야 한다.
- QR·일회용 코드는 짧은 시간 뒤 만료되고 다시 사용할 수 없어야 한다.
- 사설망·relay·ADB 중 한 계층이라도 인증에 실패하면 세션을 열지 않는다.

### FR-007 진단

- VPN 권한, Tailscale 로그인, 사설 IP, 로컬 ADB, relay, PC 접속을 각각 검사한다.
- 오류 코드와 사용자용 설명을 함께 표시한다.
- 진단 보고서를 사용자가 명시적으로 선택한 경우에만 파일로 내보낸다.
- 보고서에서 토큰, 개인 키, ADB 명령 내용과 개인정보를 제거한다.

### FR-008 네트워크 전환

- Wi-Fi에서 LTE/5G 또는 반대로 전환되면 자동 재연결을 시도한다.
- 제한된 횟수 안에 복구되지 않으면 오류 상태와 수동 재시도 버튼을 표시한다.

### FR-009 휴대형 USB 브리지

- 브리지는 Linux USB host와 ADB host로 동작하고 Fold8은 USB device와 `adbd`로 동작한다.
- Fold8의 Android 무선 디버깅은 OFF 상태에서도 원격 USB ADB가 가능해야 한다.
- 브리지는 Fold8 핫스팟을 인터넷 경로로 사용하고 자기 Tailscale node로 집 PC에 연결한다.
- 초기 스파이크는 집 PC의 Tailscale 제한 SSH 명령으로 브리지의 ADB를 사용한다.
- ADB server `5037`, `adbd 5555`와 인증 없는 관리 포트를 일반 인터페이스에 열지 않는다.
- USB 미검출, RSA 미승인, 핫스팟 없음, Tailscale 끊김과 전원 불안정을 서로 다른 상태로 보고한다.
- 부품 도착 뒤 전원·USB·네트워크·ADB Gate를 통과한 경우에만 Bridge Agent와 통합 UI를 구현한다.

## 7. 비기능 요구사항

### NFR-001 보안

- ADB 연결은 승인된 RSA 키를 요구한다.
- 직접 tunnel·Tailscale 밖의 일반 인터페이스에 ADB가 노출되는지 시험한다.
- 인증 키나 Tailscale 토큰을 APK·Git·로그에 저장하지 않는다.
- 민감한 키는 Android Keystore 또는 동등한 보호 저장소에 둔다.
- 잠금 화면에서 민감 정보와 원격 연결 시작을 제한한다.

### NFR-002 신뢰성

- LTE/Wi-Fi 전환 후 복구한다.
- 앱 프로세스가 종료되면 외부 연결이 열린 채 남지 않도록 정리한다.
- OFF 요청은 부분 실패가 있어도 가능한 통로를 모두 닫고 결과를 보고한다.
- 브리지 모드는 핫스팟 OFF/ON, USB 분리·재연결과 브리지 전원 재시작 뒤 제한된 횟수로 복구한다.
- 저전압과 USB 재열거를 네트워크 오류로 잘못 보고하지 않는다.

### NFR-003 배터리

- OFF 상태에서는 VPN·ADB 유지 서비스와 주기적 폴링을 실행하지 않는다.
- ON 상태는 Android 포그라운드 서비스 알림으로 명확히 표시한다.
- 불필요한 고주기 상태 검사와 대용량 로그 저장을 피한다.
- 브리지 모드는 보조배터리·Fold8 충전 전류, 발열과 LTE 데이터 사용량을 실측하고 미검증 값을 제품 사양으로 표시하지 않는다.

### NFR-004 접근성·반응형

- 상태를 색상만으로 구분하지 않고 문구·아이콘·위치로 함께 표시한다.
- 접힌 폰, 펼친 Fold 화면, 태블릿형 폭에서 잘림·겹침·가로 넘침이 없어야 한다.
- 주요 터치 목표는 최소 48dp를 확보한다.
- TalkBack용 레이블과 토글 상태 설명을 제공한다.

### NFR-005 공개 빌드

- GitHub Actions에서 빌드와 시험을 재현할 수 있어야 한다.
- Release APK와 로컬 산출물의 SHA-256을 비교한다.
- 소스 버전, 앱 버전, README, Release와 APK 정보가 일치해야 한다.

## 8. 완료 판정

1차 공개 후보는 다음 조건을 모두 충족해야 한다.

- Fold8 Android 17에서 앱 토글과 빠른 설정 타일 ON/OFF 성공
- Android 16 / One UI 8 실기기 또는 확보 가능한 대표 기기에서 핵심 연결 성공
- 외부 LTE/5G 휴대폰과 집 PC 사이 ADB 연결 성공
- shell, logcat, APK 설치, 파일 송수신, scrcpy 성공
- 다른 VPN 충돌 안내 정상 동작
- OFF 후 원격 ADB 연결 불가 확인
- BUILD, UNIT, INTEGRATION, LINT, STATIC CHECK, E2E, SECURITY REVIEW 통과
- 미해결 CRITICAL/HIGH 0건

휴대형 USB 브리지 지원 표시는 다음 별도 조건을 충족한 뒤에만 추가한다.

- Fold8 Android 무선 디버깅 OFF와 USB 디버깅 ON 상태에서 Pi의 `adb devices -l` 성공
- Fold8 LTE/5G + 자체 2.4GHz 핫스팟 + Pi Tailscale 동시 동작
- 집 PC에서 원격 shell·logcat과 합성 파일 push/pull SHA-256 일치
- ADB server가 bridge loopback 밖에 노출되지 않음
- USB·핫스팟·전원 분리 뒤 원격 접근 실패
- 화면 잠금, 재연결과 장시간 전원·발열 현장시험
- 초보자용 H-00~H-08 절차의 실제 화면·복구 검증

## 9. 승인 결과와 후속 미결정

- 제품명과 저장소명
- 아이콘 방향
- 1차 버전 기능 범위
- Windows PC Helper 포함 여부와 형태
- 자체 작성 코드 라이선스
- 로그 보관 정책
- 다른 VPN 충돌 처리
- 기술 스파이크와 실제 APK 구현 시작 승인
