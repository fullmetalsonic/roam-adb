# Raspberry Pi 관리자 유지보수 권한 복구

## 1. 현재 문제

2026-09-01 감사 수정 중 `roamadb` 계정의 중복 `NOPASSWD: ALL`을 제거했다. 제거 전 `passwd -S roamadb`를 확인하지 않았고, 수정 뒤 확인 결과 계정 상태는 `L`(password locked)이었다. 따라서 SSH 공개키 로그인과 RoamADB 기능은 정상이지만 일반 `sudo`에 입력할 수 있는 유효한 비밀번호가 없다.

현재 영향은 다음과 같다.

- USB ADB, 자동 USB 테더링, Tailscale과 공개키 SSH: 정상
- 안전 종료: 현재 설치된 제한 명령으로 가능
- `apt full-upgrade`, 새 root 설정 변경: 관리자 복구 전 불가
- 데이터 손실: 확인되지 않음

비밀번호를 추측하거나 전체 무암호 sudo를 영구 복원하지 않는다. 대신 SD의 FAT boot 파티션에 one-shot 복구 payload를 넣어 root 소유의 고정 유지보수 명령만 설치한다.

## 2. 복구가 설치하는 권한

`scripts/recover-locked-pi-admin.sh`는 다음 한 명령만 무암호 sudo로 허용한다.

```text
/usr/local/sbin/roamadb-maintain
```

이 root 소유 wrapper는 인수를 정확히 하나만 받고 다음 세 동작만 허용한다.

- `update`: Debian 패키지 목록과 전체 업그레이드
- `reboot`: 정상 재부팅
- `poweroff`: 파일시스템을 동기화한 뒤 정상 종료

임의 명령, 임의 파일 경로와 추가 인수는 거부한다.

## 3. 실기기 복구 절차

아직 **현장 검증 전 절차**다. 각 단계 결과를 확인하고 다음 단계로 진행한다.

1. PC에서 `scripts/roamadb-pi-poweroff.ps1`을 실행한다.
2. Pi의 초록 LED가 완전히 꺼진 것을 확인한 뒤 전원과 휴대폰 USB를 분리한다.
3. microSD를 Windows 카드리더에 넣고 `bootfs` 파티션을 연다.
4. `scripts/recover-locked-pi-admin.sh`를 bootfs 최상위에 같은 파일명으로 복사한다.
5. `cmdline.txt` 원본을 별도 파일로 백업한다. 기존 한 줄 끝에 다음 두 항목을 공백으로 구분해 추가한다.

```text
systemd.run=/boot/firmware/recover-locked-pi-admin.sh systemd.run_success_action=poweroff
```

6. `cmdline.txt`를 한 줄 형식으로 유지하고 SD를 안전하게 제거한다.
7. SD를 Pi에 장착하고 `PWR IN` 전원을 연결한다. 복구 payload가 root로 한 번 실행된 뒤 Pi가 자동으로 종료돼야 한다.
8. 초록 LED가 완전히 꺼지면 전원을 뺐다가 다시 연결해 정상 부팅한다.
9. PC에서 공개키 SSH가 복구됐는지 확인한다.
10. 다음 명령을 실행해 허용 범위가 wrapper 하나뿐인지 확인한다.

```sh
sudo -n -l
sudo -n /usr/local/sbin/roamadb-maintain update
```

11. 업데이트 후 다음 명령으로 정상 재부팅한다.

```sh
sudo -n /usr/local/sbin/roamadb-maintain reboot
```

12. 재부팅 뒤 Tailscale, SSH, USB 테더링, `adb devices -l`, loopback `5037`, 방화벽, 부팅 오류와 파일시스템 오류를 다시 확인한다.

복구 payload는 실행하면서 `cmdline.txt`에서 자기 실행 인수를 제거한다. bootfs에 `.done` 파일이 생성돼야 한다. 인수가 제거되지 않았거나 자동 종료가 발생하지 않으면 전원 재인가를 반복하지 말고 SD를 PC에 다시 연결해 원본 `cmdline.txt`를 복원한다.

## 4. 재발 방지

- 설치 스크립트는 OS 업그레이드를 권한 축소보다 먼저 실행한다.
- 비밀번호가 잠긴 headless appliance에는 전체 sudo 대신 root 소유의 고정 maintenance wrapper를 먼저 설치한다.
- 권한 축소 전후에 `passwd -S`, `sudo -n -l`, SSH 새 세션과 필요한 유지보수 명령을 별도로 시험한다.
- 안전 종료·복구 경로를 실제 통과하기 전에는 감사 항목을 CLOSED 또는 PASS로 표시하지 않는다.
