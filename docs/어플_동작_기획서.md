# RoamADB — 앱 동작 목표 기획서

## 1. 문서 상태

- 상태: 승인된 목표안, 인증·ON/OFF 기반 구현
- 앱 코드: 1차 기술 스파이크 작성
- 기본 동작: 사용자 요청형 ON/OFF
- 부팅 자동실행: 사용하지 않음

이 문서의 기존 `PC Helper` 표현은 확정 제품명 `RoamADB Gateway`를 뜻한다.

## 2. 동작 구성

```text
[Android 앱]
  ├─ 설정·상태 UI
  ├─ Quick Settings Tile
  ├─ 직접 PC tunnel 또는 Tailscale VPN
  ├─ 로컬 ADB 페어링·연결
  ├─ 인증된 ADB relay
  └─ 보안·진단·복구 관리자
             │
             ▼
[집 Windows PC]
  ├─ adb / Android Studio / scrcpy
  └─ 선택적 PC Helper
```

## 3. 최초 설정 흐름

사용자는 먼저 `집 PC 직접 연결`, `내장형 보안망`, `기존 VPN 경유 · ADB 전용` 중 하나를 선택한다. 현재 권장·구현 경로는 3번째이며, 내장형은 계획 상태로 실행을 막는다. 직접 연결은 PC Helper 외부 도달성 검사를 통과해야 한다.

### 단계 1 — 호환성 검사

1. Android 버전을 검사한다.
2. Samsung 제조사와 One UI 버전을 확인 가능한 범위에서 표시한다.
3. Android 16 미만이면 지원 대상이 아님을 알리고 진행을 중단한다.
4. 기존 VPN 경유 모드에서는 공식 Tailscale을 먼저 연결해야 하며 RoamADB가 Tailscale을 제어하지 않는다고 설명한다.

### 단계 2A — 집 PC 직접 연결

1. PC Helper의 QR 또는 6자리 코드를 입력한다.
2. PC 서버 주소와 인증서 지문을 확인한다.
3. 휴대폰 클라이언트 키를 생성하고 상호 등록한다.
4. LTE에서 PC Helper 외부 도달 시험을 수행한다.

### 단계 2B — 기존 Tailscale 경유

1. 사용자가 공식 Tailscale 앱을 별도로 열어 연결한다.
2. RoamADB로 돌아오면 Android 기본 네트워크의 VPN transport를 검사한다.
3. 활성 VPN이 없으면 Tailscale 연결과 split tunneling 제외 여부를 안내한다.
4. RoamADB는 시스템 VPN 동의 화면을 열거나 기존 VPN을 교체하지 않는다.

### 단계 3 — Tailscale 로그인

이 단계는 후속 내장형 보안망 모드의 목표이며 현재 기존 VPN 경유 모드에는 적용하지 않는다. 공식 Tailscale 앱에서 이미 로그인을 마친다.

1. 시스템 브라우저 인증을 시작한다.
2. 앱으로 복귀하면 로그인·장치 등록 상태를 검사한다.
3. 계정명 전체나 인증 토큰을 일반 로그에 기록하지 않는다.
4. 로그아웃과 재로그인 기능을 제공한다.

### 단계 4 — 무선 디버깅

1. 개발자 옵션 상태를 확인할 수 없는 경우 설정 화면 바로가기를 제공한다.
2. 사용자가 무선 디버깅을 켠다.
3. 앱은 Android 버전에 따라 연결 경로를 선택한다.
   - Android 17 이상: ADB Wi-Fi 2.0 우선
   - Android 16: 기존 페어링 포트·mDNS 방식
4. 페어링 코드와 포트를 입력한다.
5. 페어링 성공 후 자체 ADB 키를 안전하게 보관한다.
6. 실패하면 코드 만료, 포트 오류, 무선 디버깅 꺼짐을 구분한다.

### 단계 5 — 연결 시험

1. 로컬 ADB 응답을 확인한다.
2. 직접 PC tunnel 또는 Tailscale 사설 IP와 relay 준비를 확인한다.
3. PC 연결용 주소 또는 Helper 등록 정보를 표시한다.
4. 최초 설정 완료 화면을 표시한다.

## 4. 앱 토글 ON 흐름

1. 현재 잠금·선택한 네트워크 모드·페어링 상태를 검사한다.
2. 직접 모드이면 집 PC 주소·키·도달성을 확인하고 인증 tunnel을 연다.
3. 기존 VPN 경유 모드이면 공식 Tailscale이 먼저 연결됐는지 확인하고, RoamADB가 별도 VPN을 시작하지 않은 채 Gateway TLS 연결을 연다.
4. 로컬 ADB 포트 또는 세션을 탐지한다.
5. 필요하면 ADB 연결을 복구한다.
6. 선택한 공급자의 인증된 relay를 연다.
7. 허용 범위 밖 노출 여부를 내부 진단으로 검사한다.
8. relay가 준비되면 `원격 디버깅 준비됨` 상태로 전환한다.
9. PC가 실제 접속하면 `PC 연결됨` 보조 상태를 표시한다.

ON 성공은 PC 전원이 꺼져 있어도 가능하다. ON의 완료 기준은 휴대폰 쪽 원격 연결 준비까지이며 PC 접속 여부는 별도로 표시한다.

## 5. 빠른 설정 타일 흐름

### 최초 설정 미완료

- 타일을 누르면 앱 최초 설정 화면을 연다.
- 타일은 `설정 필요` 상태를 표시한다.

### OFF에서 ON

- 화면이 안전하게 잠겨 있으면 잠금 해제를 요구한다.
- 권한과 설정이 유효하면 연결을 시작한다.
- 타일을 `연결 중`으로 표시한다.
- 준비되면 `켜짐`으로 변경한다.
- 오류면 `문제 있음` 상태와 앱 열기 동작을 제공한다.

### ON에서 OFF

- relay를 닫는다.
- 로컬 ADB 외부 진입점을 닫는다.
- 직접 tunnel 또는 Tailscale VPN 세션을 종료한다.
- 포그라운드 서비스를 종료한다.
- 타일을 `꺼짐`으로 갱신한다.

## 6. OFF 흐름과 보존 정책

### 종료 대상

- 외부 ADB relay
- 직접 tunnel 또는 Tailscale VPN 세션
- 재연결 작업
- ON 상태 포그라운드 알림
- 세션 임시 포트와 연결 정보

### 기본 보존 후보

- 직접 PC 등록 또는 Tailscale 로그인 자격
- Tailscale 모드의 VPN 승인 상태
- 앱 자체 ADB 페어링 키
- relay가 허용한 PC 신원·지문
- 사용자 설정
- 제한된 진단 이력

### 별도 초기화로 삭제

- 직접 PC 등록 삭제 또는 Tailscale 로그아웃
- ADB 페어링 초기화
- relay 허용 PC 전체 삭제
- Android 시스템 ADB 승인 취소 화면 열기
- 앱 데이터와 진단 로그 삭제

## 7. 상태 모델

| 상태 | 의미 | 사용자 행동 |
|---|---|---|
| `SETUP_REQUIRED` | 필수 권한·로그인·페어링 미완료 | 설정 시작 |
| `OFF` | 모든 원격 통로 종료 | ON 가능 |
| `STARTING_VPN` | 사설망 연결 중 | 대기 또는 취소 |
| `DISCOVERING_ADB` | 로컬 ADB 탐지 중 | 대기 |
| `PAIRING_REQUIRED` | 페어링 없음·만료 | 다시 페어링 |
| `STARTING_RELAY` | 사설망 relay 준비 중 | 대기 또는 취소 |
| `READY` | 휴대폰 원격 디버깅 준비 완료 | PC 연결 가능 |
| `PC_CONNECTED` | 하나 이상의 허용 PC 접속 | 디버깅 가능 |
| `RECOVERING` | 네트워크 변경 후 복구 중 | 대기 또는 중지 |
| `STOPPING` | 통로 정리 중 | 대기 |
| `ERROR` | 자동 복구 불가 | 해결 안내·재시도 |

## 8. 네트워크 전환

1. LTE, 5G, Wi-Fi 변경을 감지한다.
2. 기존 relay와 VPN 상태를 확인한다.
3. 짧은 지수 백오프로 제한된 횟수만 재연결한다.
4. 성공하면 `READY` 또는 `PC_CONNECTED`로 복귀한다.
5. 실패하면 `ERROR`로 전환하고 원인과 수동 재시도를 표시한다.
6. 반복 실패로 배터리를 소모하지 않는다.

## 9. 다른 VPN 충돌

Android는 사용자 프로필당 활성 VPN을 하나만 허용한다.

현재 기존 VPN 경유 모드:

1. 공식 Tailscale을 사용자가 먼저 연결한다.
2. RoamADB는 VPN을 새로 만들거나 기존 VPN을 종료하지 않는다.
3. 활성 VPN transport가 없으면 등록·ON을 차단한다.
4. 다른 VPN이 활성화돼 있어도 패키지 종류를 단정하지 않고 실제 Gateway 연결 결과로 판정한다.

후속 내장형 모드 정책:

1. 다른 VPN이 준비·활성화되어 있음을 감지한다.
2. 기존 VPN을 자동 종료하지 않는다.
3. `기존 VPN이 중지될 수 있음`을 표시한다.
4. 사용자가 명시적으로 계속을 선택한 경우에만 Android VPN 권한 흐름으로 이동한다.
5. 우리 VPN 권한이 회수되면 `ERROR_VPN_REVOKED`로 전환하고 relay를 닫는다.

## 10. 오류 분류

| 코드 | 원인 후보 | 사용자 안내 |
|---|---|---|
| `VPN_PERMISSION_REQUIRED` | VPN 권한 없음 | 시스템 승인 열기 |
| `VPN_CONFLICT` | 다른 VPN 활성 | 기존 VPN 확인 후 재시도 |
| `VPN_NOT_ACTIVE` | 기존 VPN 경유 모드에서 활성 VPN 없음 | 공식 Tailscale 연결·split tunneling 확인 |
| `TAILSCALE_LOGIN_REQUIRED` | 로그인 없음·만료 | 로그인 |
| `WIRELESS_DEBUG_OFF` | 무선 디버깅 꺼짐 | 개발자 옵션 열기 |
| `PAIR_CODE_EXPIRED` | 코드 만료 | 새 코드 발급 |
| `ADB_DISCOVERY_FAILED` | mDNS·포트 탐지 실패 | 포트 직접 입력·재시도 |
| `ADB_AUTH_FAILED` | 키 거부·폐기 | 페어링 초기화 |
| `RELAY_BIND_FAILED` | 포트·인터페이스 오류 | 진단 실행 |
| `NETWORK_CHANGED` | LTE/Wi-Fi 변경 | 자동 복구 중 표시 |
| `SECURITY_EXPOSURE` | 허용 범위 외 접근 감지 | 연결 즉시 중지 |

## 11. PC 동작 후보

### 최초 PC 등록

1. PC Helper에서 `휴대폰 등록`을 누른다.
2. Helper가 QR과 6자리 일회용 코드를 표시한다.
3. 휴대폰 `PC 추가`에서 QR을 스캔하거나 코드를 입력한다.
4. 휴대폰은 Tailscale LocalAPI로 PC 장치 신원을 확인한다.
5. 양쪽 코드와 PC 이름이 같으면 사용자가 `이 PC 허용`을 누른다.
6. Helper가 로컬 ADB 접속점을 만들고 Android 버전에 맞는 무선 ADB 페어링·키 승인까지 완료한다.

### 표준 도구

```powershell
adb connect <앱이 표시한 주소>
adb devices -l
scrcpy -s <장치 식별자>
```

위 명령은 설계 예이며 현재 실행·검증하지 않았다.

### PC Helper

- ADB 설치 위치 자동 탐색
- Tailscale 연결 확인
- 휴대폰 주소와 relay 포트 등록
- 연결·연결 해제
- `adb devices -l` 결과 표시
- scrcpy 실행
- 진단 보고서 생성
- Codex에서 호출 가능한 CLI 제공

PC Helper의 relay 인증과 Android 시스템 기본 ADB 인증은 별도 계층이다. Helper 등록을 삭제하면 relay를 즉시 차단하고, Android ADB 승인 전체 취소는 개발자 옵션으로 안내한다.

## 12. 승인 결과와 후속 확정 필요

앱 이름, 수동 ON/OFF, 빠른 설정 타일, 부팅 자동시작 제외와 `RoamADB Gateway` 포함은 승인됐다. 아래 세부 ADB·scrcpy·Tailscale 동작은 기술 스파이크 결과에 따라 후속 확정한다.

- 다른 VPN 충돌 시 단순 차단 또는 사용자 확인 후 교체
- 진단 로그 기본 보관 기간
- relay 허용 PC 목록의 표시 이름과 신원·지문 형식
- PC Helper를 1차 버전에 포함할지 여부
- scrcpy 설치·업데이트를 Helper가 담당할지 여부
