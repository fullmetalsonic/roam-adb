# RoamADB 휴대형 USB ADB 브리지 실기기 검증 — 2026-09-01

## 1. 결론

Raspberry Pi Zero 2 W를 USB host 겸 ADB host로 구성하고, Samsung Galaxy Z Fold8(Android 17 / One UI 9)을 실제 USB로 연결했다. Windows PC에서 Pi의 Tailscale 주소로 SSH 접속해 Pi의 ADB를 실행하고 휴대폰 셸 명령과 합성 파일 왕복을 완료했다. 휴대폰 핫스팟을 완전히 끄고 PC는 독립된 집 인터넷, Pi는 휴대폰 모바일 데이터 기반 USB 테더링만 사용한 분리망 시험도 통과했다. PC와 휴대폰이 실제로 지리적으로 떨어진 현장 시험은 아직 수행하지 않았다.

최종 인터넷 경로는 다음 순서다.

1. **주 경로:** Fold8 모바일 데이터 → USB 테더링 → Pi
2. **예비 경로:** Fold8 모바일 데이터 → 2.4GHz 핫스팟 → Pi Wi-Fi

ADB는 두 경우 모두 Fold8과 Pi 사이의 실제 USB 연결을 사용한다. Android 무선 디버깅, 6자리 무선 페어링, 공인 ADB 포트와 공유기 포트포워딩은 사용하지 않는다.

```text
Fold8 USB adbd ───────────────┐
Fold8 USB tethering ──────────┼─ 같은 USB 연결 ─> Pi Zero 2 W
Fold8 2.4 GHz hotspot(예비) ──┘                    │
                                                  │ Tailscale + SSH
                                                  ▼
                                                집 PC
```

## 2. 설치된 구성

| 항목 | 실제 구성 |
|---|---|
| 하드웨어 | Raspberry Pi Zero 2 W, 32GB microSD, OTG host 어댑터, 별도 `PWR IN` 전원 |
| OS | Raspberry Pi OS Lite 64-bit / Debian 13 Trixie |
| 원격망 | Pi의 독립 Tailscale node |
| 원격 관리 | 공개키 SSH, 비밀번호·root 로그인 비활성화, 전체 무암호 sudo 제거 |
| ADB | Debian `adb` 34.0.5, 사용자 전용 ADB service |
| ADB listener | `127.0.0.1:5037`만 사용 |
| USB host driver | Zero 2 W 전용 `dwc2,dr_mode=host` |
| USB 테더링 자동화 | USB 장치 `udev` 이벤트 → 최대 30초 제한 `roamadb-auto-tether.service` |
| 인터넷 우선순위 | USB metric 100, Wi-Fi metric 600 |
| 복구 경로 | Tailscale SSH 또는 직접 USB 네트워크 SSH, 설치 전 설정의 타임스탬프 백업 |
| 안전 종료 | PC의 `scripts/roamadb-pi-poweroff.ps1` → Pi의 제한된 `roamadb-poweroff` |
| Tailscale 인증 | 시험 tailnet의 기존 기기 네 대 모두 node key 만료 없음 |

USB 테더링 자동화는 승인된 ADB 장치가 연결되면 Android의 RNDIS 기능을 켠다. 처음 연결하는 휴대폰은 해당 휴대폰 화면에서 Pi의 ADB RSA 키를 한 번 승인해야 한다. 이후에는 USB 디버깅이 켜진 휴대폰을 Pi에 연결하는 것만으로 USB 테더링과 ADB가 함께 준비된다.

합성 파일 시험에는 저장소의 공개 README 사본만 사용했으며 사용자 자료에는 접근하지 않았다. 공개 문서에는 SSID, 비밀번호, IP, MAC, Tailscale 계정, SSH 키, 휴대폰 일련번호를 포함하지 않는다.

### 콜드부팅 USB 인식 결함과 수정

최초 보조배터리 시험에서는 휴대폰 케이블을 미리 연결한 채 Pi를 부팅하면 전원 LED와 OS 부팅은 정상이지만 Samsung USB 장치가 커널에 열거되지 않았다. 당시 자동 테더링 timer는 실행 중이었으나 ADB 장치 자체가 없어서 복구할 수 없었고, 케이블을 물리적으로 다시 꽂은 뒤에야 ADB와 RNDIS가 생성됐다.

조사 결과 `dtoverlay=dwc2,dr_mode=host` 줄이 `config.txt`의 `[cm5]` 구역에만 있어 Zero 2 W에는 적용되지 않았고, 실제 USB root hub는 deprecated된 `dwc_otg` 드라이버를 사용하고 있었다. `scripts/configure-pi-zero2-usb-host.sh`로 원본 설정을 타임스탬프 백업한 뒤 Zero 2 W 전용 `[pi02]` 구역에 `dwc2,dr_mode=host`를 적용했다.

휴대폰 케이블을 그대로 둔 채 3회 연속 재부팅한 결과 매번 `dwc2`가 부팅 첫 단계에서 Samsung 장치를 열거했다. 사용자의 재연결 없이 `rndis,adb`, `usb0` 기본 경로, Tailscale, SSH와 ADB가 자동 복구됐고, 첫 수정 재부팅 뒤 PC→Pi→휴대폰→Pi 파일 왕복의 SHA-256도 일치했다. 3회 반복은 `PASS`지만 목표인 10회, 장시간 유지와 보조배터리 소모 시험은 아직 미실행이다.

## 4. 실제 사용 절차

### 최초 한 번

1. 휴대폰에서 개발자 옵션과 USB 디버깅을 켠다.
2. Pi `PWR IN`에 안정적인 전원을 연결한다.
3. Pi `USB` 포트의 OTG host 어댑터와 휴대폰을 데이터 케이블로 연결한다.
4. 휴대폰의 ADB RSA 창에서 이 Pi를 승인한다.
5. Pi를 사용자 tailnet의 별도 node로 등록한다.

### 이후 사용

1. Pi 전원을 연결한다.
2. USB 디버깅이 켜진 휴대폰을 Pi에 연결한다.
3. Pi가 USB 테더링을 자동 활성화한다.
4. 집 PC에서 Tailscale을 통해 Pi에 SSH 접속하고 Pi의 `adb`를 실행한다.
5. 사용을 마치면 집 PC에서 `scripts/roamadb-pi-poweroff.ps1`을 실행하고 초록 LED가 완전히 꺼진 뒤 보조배터리를 분리한다.

휴대폰의 Tailscale 앱, Android 무선 디버깅과 6자리 페어링 코드는 이 경로에 필요하지 않다. USB 테더링을 사용할 수 없는 경우에는 저장된 2.4GHz 핫스팟이 예비 인터넷 경로가 된다.

## 5. 남은 제한과 다음 게이트

- 다른 휴대폰은 최초 연결 시 각 휴대폰에서 ADB RSA 승인이 한 번 필요하다.
- 휴대폰은 현재 케이블과 USB 역할에서 Pi에 부팅 전원을 공급하지 못했다. `PWR IN`의 별도 5V 전원 또는 보조배터리가 필수이며, 전원 방향이 검증되지 않은 Y 케이블은 사용하지 않는다.
- 통신사 또는 제조사 정책으로 USB 테더링이 차단된 기기는 핫스팟 예비 경로를 사용한다.
- 현 단계 원격 명령은 Tailscale SSH 안에서 Pi의 `adb`를 실행한다. 공개 ADB 포트는 만들지 않는다.
- node key 만료를 껐으므로 분실·도난 시 Tailscale 관리 화면에서 해당 기기를 즉시 제거해야 한다.
- 현재 tailnet의 기본 grant는 기기 간 all-to-all이다. Pi 자체 SSH 공개키·인터페이스 방화벽은 적용됐지만 tailnet ACL 최소화는 별도 영향 검토 후 수행한다.
- 현재 Pi 계정은 비밀번호가 잠긴 상태다. 감사 수정 순서를 잘못 적용해 일반 sudo가 잠겼으며, `라즈베리파이_관리자_복구.md`의 실기기 복구를 마치기 전에는 관리자 작업을 완료했다고 보지 않는다.
- 지리적으로 분리된 집 PC·외부 휴대폰, 장시간 유지, 다회 재부팅과 전력 소비량은 추가 현장 시험이 필요하다.
- Windows Gateway, Android 앱, scrcpy와 Android Studio의 제품형 통합은 별도 H-08 승인·구현 대상이다. 현재 공개 `v0.1.2-spike`가 이 하드웨어 경로를 지원한다고 표시하지 않는다.
