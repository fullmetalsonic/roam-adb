## 3. 검토 중 발견·수정한 사항

### USB-R-001 현재 릴리스와 계획 기능 혼동

- 문제: 새 계획만 덧붙이면 사용자가 `v0.1.2-spike`가 USB bridge를 지원한다고 오해할 수 있다.
- 수정: README와 모든 기준 문서에서 현재 무선 경로는 구현·공개, `portable-usb-bridge`는 계획·미구현으로 분리했다.
- 재발방지: USB bridge 지원 표시는 H-001~H-301과 보안 노출 시험 통과 뒤에만 허용한다.

### USB-R-002 단일 APK 목표와 외부 하드웨어 경로 충돌

- 문제: 기존 요구사항은 휴대폰 단일 APK를 유일한 제품 구조처럼 기술했다.
- 수정: 단일 APK 목표를 기존·후속 소프트웨어 경로에 유지하면서 외부 Linux ADB host를 선택 transport로 추가했다.
- 재발방지: 모드 식별자와 완료 기준을 `existing-vpn-adb-only`, `portable-usb-bridge`로 구분했다.

### USB-R-003 전원 최소값과 USB host 안정성

- 문제: 초기 메모의 5V 2A 최소값은 Fold8 USB 연결까지 고려한 공개 권장값으로 부족할 수 있다.
- 근거: 현재 Raspberry Pi 설치 문서는 Zero 계열에 5V 2.5A 전원을 권장한다.
- 수정: 공개 BOM과 시험 환경을 5V 2.5A 이상으로 통일하고 PWR IN·USB 포트 분리, 임의 Y 케이블 금지를 기록했다.
- 재발방지: H-004에서 저전압·재부팅·USB 재열거를 실제 확인한다.

### USB-R-004 ADB server 공개 위험

- 문제: Pi의 `adb` server를 Tailscale 또는 핫스팟에 직접 열면 5037의 인증 경계가 약해질 수 있다.
- 수정: 1차 경로를 Tailscale 제한 SSH 내부 명령으로 고정하고, PC 표준 ADB는 loopback SSH forwarding만 시험한다. `adb -a`, 5037·5555 공개를 금지했다.
- 재발방지: H-105·H-106에서 핫스팟·공인 listener 0건을 확인한다.

### USB-R-005 하드웨어 미검증을 완료로 오인

- 문제: 공식 사양 확인만으로 Fold8 hotspot+USB ADB+Tailscale E2E를 PASS 처리할 위험이 있다.
- 수정: 모든 하드웨어 항목을 `HARDWARE REQUIRED` 또는 `NOT RUN`으로 표시했다.
- 재발방지: H-001~H-406의 실제 증거와 현장 검증 기록 형식을 사용한다.

### USB-R-006 초보자 오류가 한 상태로 합쳐짐

- 문제: 전원, 2.4GHz hotspot, Tailscale, USB 케이블과 RSA 승인이 모두 `연결 실패`로 보이면 복구가 어렵다.
- 수정: `BRIDGE_POWER_UNSTABLE`, `BRIDGE_HOTSPOT_NOT_FOUND`, `BRIDGE_TAILSCALE_OFFLINE`, `BRIDGE_USB_MISSING`, `BRIDGE_ADB_UNAUTHORIZED`를 분리했다.
- 재발방지: H-00~H-08에서 각 단계의 예상 화면·출력을 확인한 뒤 다음 단계로 진행한다.
