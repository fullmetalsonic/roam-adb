# RoamADB 누적 인수인계

## 1. 목적과 저장소

- 공개 저장소: `fullmetalsonic/roam-adb`
- 현재 방향: 기존 Android 무선 디버깅 경로와 Raspberry Pi Zero 2 W 기반 `portable-usb-bridge`를 한 저장소에서 함께 관리한다.
- 분리 원칙: 하드웨어 Bridge Agent가 독립 제품·릴리스 주기를 가져야 할 정도로 커질 때 별도 저장소 또는 브랜치를 검토한다. 그 전에는 문서·설치 스크립트·시험 기록을 현 저장소에 유지한다.
- 공개 문서와 로그에는 비밀번호, 해시, SSH 키, SSID, IP, MAC, 기기 일련번호와 Tailscale 계정 정보를 넣지 않는다.

## 2. 현재 권장 구조

```text
Fold8 USB adbd ───────────────┐
Fold8 USB tethering(주 경로) ─┼─ USB ─> Pi Zero 2 W ─> Tailscale ─> 집 PC
Fold8 2.4GHz hotspot(예비) ───┘
```

- ADB는 휴대폰과 Pi 사이의 실제 USB를 사용한다.
- Pi 인터넷은 같은 USB의 휴대폰 USB 테더링을 우선하고 저장된 2.4GHz 핫스팟을 예비로 쓴다.
- Android 무선 디버깅, 6자리 페어링, 공유기 포트포워딩과 공인 ADB 포트는 필요하지 않다.
- Pi에는 별도 `PWR IN` 전원 또는 보조배터리가 필수다. 휴대폰만으로 Pi 전원을 공급하는 시험은 실패했다.
- 현재 원격 명령은 Tailscale로 제한된 SSH 안에서 Pi의 로컬 `adb`를 실행한다.

## 3. 구현된 Pi 구성

- Raspberry Pi OS Lite 64-bit / Debian 13
- Zero 2 W `dwc2,dr_mode=host`
- USB ADB host와 `127.0.0.1:5037` 전용 ADB server
- USB 장치 event 기반 자동 USB 테더링과 Wi-Fi fallback
- USB 경로 우선 metric, Wi-Fi 후순위 metric
- Tailscale node와 공개키 전용 SSH
- SSH 시작 전 인터페이스 방화벽
- 전체 `NOPASSWD: ALL` 제거
- 고정 동작만 허용하는 root 소유 `roamadb-poweroff`, `roamadb-maintain`
- 설정 백업·복원, 안전 종료, 잠긴 관리자 계정 one-shot 복구 스크립트

## 4. 2026-09-01~02 실제 검증

### 기능 PASS

- Fold8 USB ADB 승인·shell·합성 파일 SHA-256 왕복
- USB 테더링 단독 인터넷과 핫스팟 fallback
- PC와 Pi가 서로 다른 인터넷을 쓴 Tailscale SSH·ADB
- 실제 USB 분리·재연결 자동 복구
- 휴대폰 케이블 선연결 콜드부팅 3회
- hotspot OFF 상태에서 event 기반 RNDIS·ADB 복구
- 안전 종료 명령과 다음 정상 부팅
- 커널 업데이트 뒤 Fold8 USB ADB, 자동 `rndis,adb`, usb0 인터넷 HTTP 204와 52바이트 합성 파일 SHA-256 왕복

### 관리자 복구 PASS

- 문제: 비밀번호가 잠긴 계정에서 전체 무암호 sudo를 먼저 제거해 업데이트가 차단됐다.
- 첫 one-shot 실패: `systemd.run` service는 생성됐지만 영구 `multi-user.target`이 우선되어 시작되지 않았다.
- 수정: `systemd.unit=kernel-command-line.target`을 명시하고 성공 뒤 복구 인수 세 개를 제거한다.
- 결과: 계정 `P`, 임시 비밀번호 해시 삭제, `.done` 생성, cmdline 원상복구
- 권한: 일반 명령의 `sudo -n` 거부, 고정 maintenance·safe-poweroff wrapper만 무암호 허용
- 업데이트: 95개 upgrade·8개 신규 설치, 잔여 upgrade 0
- 재부팅: 커널 `6.18.39+rpt-rpi-v8`, 실패 systemd unit 0
- 서비스: SSH·Tailscale·ADB·SSH 방화벽 active·enabled

비밀번호 평문은 PC 파일, 저장소, 명령 기록과 채팅에 저장하지 않았다. 이후에도 사용자 비밀번호를 명령 인수나 문서로 받지 않는다.

## 5. 실패·제약

- 휴대폰 단독 전원: FAIL, 별도 Pi 전원 필수
- 첫 설치·복구 UX: FAIL 후 개선. 수동 화면 안내, 네트워크 선택과 첫 one-shot 누락으로 불필요한 반복 작업이 발생했다.
- 초록 ACT LED: 종료 단독 판정 기준으로 부적합. 안전 종료 후 Tailscale·SSH 응답 종료로 확인한다.
- Tailscale ACL: 현재 기본 all-to-all이다. Pi 자체 SSH 키·방화벽은 적용됐지만 tailnet 전체 정책 변경은 다른 기기 영향 때문에 사용자 승인 전 수행하지 않는다.
- Tailscale node key 만료는 현재 시험 기기에서 껐다. 분실 시 관리 화면에서 즉시 기기를 제거해야 한다.

## 6. 아직 남은 검증

- 허용되지 않은 tailnet node와 hotspot client의 실제 접근 거부
- 지리적으로 분리된 집 PC·외부 휴대폰 종단 간 시험
- USB 20회 재연결, 전원 재시작 10회, 30분·4시간 유지와 전력·발열
- SSH local forwarding을 이용한 PC 표준 ADB, APK 설치·삭제, scrcpy와 Android Studio
- Android 16 / One UI 8 호환 기기
- Android 앱·Windows Gateway에 portable bridge 흐름을 통합할지 별도 승인

실행하지 않은 항목은 PASS로 올리지 않는다. 공개 `v0.1.2-spike` APK/EXE는 아직 하드웨어 브리지 통합 버전이 아니다.

## 7. 다음 작업자 체크리스트

1. `git status`와 이 문서의 마지막 검증 상태를 맞춘다.
2. Pi 원격 관리에는 공개키 SSH와 고정 wrapper를 우선한다.
3. root 작업에 사용자 비밀번호가 필요하면 평문을 채팅·명령 인수·파일로 받지 않는다.
4. 하드웨어 시험은 `변경 지점 → 실제 케이블 → 재부팅 회귀` 순서로 실행한다.
5. 문서에는 `PASS / FAIL / 미실행 / 현장 검증 필요`를 실제 증거대로 기록한다.
6. 공개 게시 전 민감정보와 로컬 절대경로를 검사한다.
