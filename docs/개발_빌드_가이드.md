# RoamADB 개발·빌드 가이드

## 1. 현재 기술 스파이크 기준

- Windows 11
- Microsoft OpenJDK 21
- Gradle Wrapper 8.9
- Android Gradle Plugin 8.7.3
- Kotlin 2.0.21
- Android SDK Platform 35 / Build Tools 35
- .NET SDK 10.0.400

Android 앱은 Android 16(API 36) 이상에서만 화면상 연결을 허용한다. 현재 로컬 SDK 제약 때문에 빌드는 `minSdk/compileSdk/targetSdk 35`로 수행하며, 공개 후보 전에 API 36 이상 SDK로 올려 최소 버전을 manifest 수준에서도 강제한다.

## 2. Android 준비

1. Android Studio와 Android SDK Platform 35를 설치한다.
2. Microsoft OpenJDK 21을 설치한다.

```powershell
winget install --id Microsoft.OpenJDK.21 --exact
```

3. `android/local.properties`에 로컬 SDK 경로를 기록한다. 이 파일은 Git에서 제외된다.

```properties
sdk.dir=C\:\\Users\\사용자명\\AppData\\Local\\Android\\Sdk
```

4. 프로젝트 루트에서 검증 스크립트를 실행한다.

```powershell
.\scripts\build-android.ps1
```

성공 결과는 `android/app/build/outputs/apk/debug/app-debug.apk`이다. 스크립트가 APK SHA-256도 출력한다.

### 한글 경로 처리

Android Gradle 경로 검사를 허용하되, Windows Gradle 시험 실행기의 인자 파일 문제를 피하기 위해 `core-model` 빌드 출력만 가장 가까운 영문 상위 경로의 `.roamadb-build`로 분리한다. 소스와 APK는 원래 프로젝트 경로에 남는다.

## 3. Gateway 준비

저장소의 `global.json`은 .NET SDK 10.0.400을 고정한다. 시스템에 해당 SDK가 없으면 프로젝트 로컬 `.tools/dotnet`을 사용할 수 있으며 `.tools`는 Git에서 제외된다.

```powershell
.\scripts\test-gateway.ps1
```

스크립트는 다음을 순서대로 검사한다.

1. Release 빌드
2. Gateway 자동시험
3. CLI Release 빌드
4. `doctor` 로컬 준비상태

배포용 Windows x64 단일 실행파일을 만들고 그 파일의 `doctor`까지 실행하려면 다음을 사용한다.

```powershell
.\scripts\publish-gateway.ps1
```

산출물은 `artifacts/gateway/win-x64/RoamADBGateway.exe`이며 빌드 산출물이므로 Git에는 포함하지 않는다.

## 4. Gateway 수동 실행

### 기본 loopback 진단 모드

```powershell
.\.tools\dotnet\dotnet.exe run `
  --project .\src\gateway\RoamADB.Gateway.Cli\RoamADB.Gateway.Cli.csproj `
  -c Release -- register
```

- 6자리 코드는 2분·1회용이다.
- 인증서 SHA-256 지문을 휴대폰 앱에 정확히 입력한다.
- 옵션을 생략하면 보안을 위해 `127.0.0.1:47156`에만 수신한다.
- 인증된 휴대폰이 `connect` relay를 게시하면 PC에서 `adb connect 127.0.0.1:47157`을 사용한다.
- `127.0.0.1:47158`은 최초 ADB pairing용으로 예약했지만 Android pairing UI는 아직 구현 전이다.
- 공유기 포트포워딩, 외부 방화벽 규칙과 DMZ는 아직 설정하지 않는다.

다른 창에서 상태를 확인한다.

```powershell
.\.tools\dotnet\dotnet.exe run `
  --project .\src\gateway\RoamADB.Gateway.Cli\RoamADB.Gateway.Cli.csproj `
  -c Release -- status
```

### 기존 Tailscale 경유 · ADB 전용 모드

PC와 휴대폰의 공식 Tailscale 앱이 이미 연결돼 있을 때 사용한다.

```powershell
.\artifacts\gateway\win-x64\RoamADBGateway.exe register --tailnet
```

`--tailnet`은 shell 문자열, `PATH`, Gateway 옆의 동명 실행파일이나 사용자가 입력한 임의 IP를 사용하지 않는다. Windows Program Files에 설치된 공식 Tailscale CLI에 `tailscale ip -4`를 직접 실행하고, 반환된 주소가 `100.64.0.0/10`인지 검증한 뒤 그 정확한 단일 주소에만 bind한다. `0.0.0.0`, 일반 LAN 주소와 공인 주소는 거부한다.

앱에서 `기존 VPN 경유 · ADB 전용 (권장)`을 선택하고 Gateway가 표시한 Tailscale IPv4, 포트, 지문, 코드를 입력한다. 이후 평상시에는 다음을 실행한다.

```powershell
.\artifacts\gateway\win-x64\RoamADBGateway.exe run --tailnet
.\artifacts\gateway\win-x64\RoamADBGateway.exe status --tailnet
```

- 공유기 포트포워딩과 DMZ는 필요 없다.
- Windows 방화벽은 자동으로 바꾸지 않는다.
- ADB connect/pairing relay는 계속 `127.0.0.1`에서만 열린다.
- Tailscale Android split tunneling에서 RoamADB를 제외하지 않는다.
- 상세 순서는 `기존_Tailscale_ADB_전용_모드.md`를 따른다.

## 5. 현재 검증 한계

- 실제 Fold8 설치·실행: 미실행
- Android 앱 ↔ Gateway 실기기 TLS 등록: 미실행
- 무선 ADB raw byte 중계 자동시험: PASS, 실제 Fold8 adbd 연결은 미실행
- 무선 ADB 최초 페어링 UI와 mDNS 자동 탐색: 미구현
- 집 밖 LTE/5G ↔ 집 PC: Tailscale 경로 코드 구현, 실제 Fold8 E2E는 미실행
- Tailscale 내장 모드: 미구현

따라서 현재 APK는 인증 통로, 수동 ADB connect 포트와 raw relay를 확인하는 기술 스파이크이며, 실기기·외부망 검증이 끝난 원격 ADB 제품은 아니다.
