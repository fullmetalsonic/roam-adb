# RoamADB — 네트워크 독립성 선택안

용어: 아래 `RoamADB Helper` 또는 `PC Helper`는 확정 명칭 `RoamADB Gateway`를 뜻한다.

## 1. 구분해야 할 두 의미

- 단일 앱: 휴대폰에 RoamADB APK 하나만 설치
- 완전 독립망: Tailscale 회사의 계정·제어 서버·DERP에 의존하지 않음

현재 기술 기획은 `단일 앱`이지만 네트워크 제어 평면은 Tailscale 서비스를 이용하는 안이다. 완전 독립망으로 확정한 상태는 아니다.

## 1.1 선택 D — 각 사용자 집 PC가 직접 서버

### 구성

- 집 PC의 RoamADB Helper가 인증된 TLS/QUIC 서버 역할
- 휴대폰 앱이 외부에서 집 PC로 직접 연결
- 공유기 포트포워딩 또는 외부 접근 가능한 IPv6 사용
- PC 인증서 지문과 휴대폰 키를 QR로 상호 등록
- Tailscale·Headscale 제어 서버 불필요

### 장점

- 사용자마다 자기 PC와 키를 직접 소유
- 중앙 서비스와 계정 불필요
- 데이터가 휴대폰과 집 PC 사이에 직접 흐름
- 자체 중앙 서버 운영비 없음

### 단점

- 집 회선이 공인 IPv4·IPv6로 외부 접근 가능해야 함
- 공유기·Windows 방화벽·DDNS 설정 필요 가능
- CGNAT이면 직접 연결 불가
- PC가 켜져 있어야 함

## 2. 선택 A — Tailscale 서비스 이용

### 구성

- 휴대폰: Tailscale 오픈소스 클라이언트를 내장한 RoamADB
- PC: 공식 Tailscale + RoamADB Helper
- 제어 평면: Tailscale 조정 서비스
- 데이터 평면: 가능한 경우 휴대폰과 PC가 WireGuard로 직접 연결
- 직접 연결 불가: Tailscale DERP가 종단간 암호화된 패킷을 relay

### 장점

- 별도 서버 운영 불필요
- NAT traversal과 LTE·CGNAT 대응이 검증됨
- 로그인, 장치 제거, Grants와 진단 기능 재사용
- 가장 빠르게 실제 Fold8 기술 스파이크 가능

### 단점

- Tailscale 계정과 제어 서버에 의존
- 장치 등록·공개키·정책 등 제어 평면 메타데이터가 Tailscale 서비스에 존재
- 직접 연결 실패 시 공식 DERP 사용 가능
- Tailscale 서비스 정책·API 변경을 추적해야 함

## 3. 선택 B — Headscale 자체 운영

### 구성

- 휴대폰·PC 클라이언트는 Tailscale 프로토콜과 WireGuard 데이터 평면 사용
- 제어 평면은 오픈소스 Headscale을 사용자 소유 서버에 설치
- 완전한 relay 독립이 필요하면 자체 DERP도 운영

### 장점

- 장치 등록·키 배포·정책 제어 서버를 직접 소유
- Tailscale SaaS 계정 의존을 줄임
- 개인·소규모 tailnet 용도에 맞는 공개 소스

### 단점

- 24시간 접근 가능한 서버, 도메인, TLS, 업데이트, 백업과 장애 대응 필요
- 집 회선만으로 운영하면 정전·공유기·CGNAT 문제 가능
- 자체 DERP까지 운영하지 않으면 relay 경로는 여전히 외부 인프라에 의존할 수 있음
- 앱 최초 설정과 지원 문서가 복잡해짐

## 4. 선택 C — 완전 자체 프로토콜·중계

### 구성

- 자체 장치 등록·인증
- 자체 NAT traversal, STUN/TURN 또는 reverse tunnel
- 자체 relay 서버
- 자체 키 회전·정책·장치 회수

### 장점

- 제품과 인프라를 전부 통제
- Tailscale 프로토콜·서비스 의존 없음

### 단점

- 공개 소스를 조합해도 인증, 키 회전, NAT traversal, relay, 장애 복구와 보안감사 범위가 가장 큼
- 서버 운영이 필요
- Tailscale·Headscale 방식보다 초기 실기기 완성까지 시간이 길어짐

## 5. 비교

| 항목 | D 집 PC 직접 서버 | A Tailscale | B Headscale | C 완전 자체 relay |
|---|---|---|---|---|
| 휴대폰 앱 수 | 1 | 1 | 1 | 1 |
| 중앙 서버 | 없음 | Tailscale | 사용자 서버 | 사용자 서버 |
| 공유기 설정 | 필요 가능 | 불필요 | 서버 위치에 따라 필요 | 필요 |
| CGNAT 대응 | 직접은 어려움 | 쉬움 | relay 구성 시 가능 | 직접 구현 |
| 초기 개발량 | 중간 | 가장 작음 | 중간 | 가장 큼 |
| 사용자 운영 | PC Helper·공유기 | 거의 없음 | 서버 운영 | 서버·relay 운영 |
| 현재 기술자료 | 설계 충분, 회선 진단 필요 | 충분 | 추가 배포 설계 | 추가 보안감사 |

## 6. 추천

- 집 회선에서 외부 직접 접속이 가능하고 자체 PC만 쓰고 싶음: 선택 D
- 공유기 설정 없이 빠르게 실제 동작시키는 것이 우선: 선택 A
- Tailscale 회사 서버 의존을 피하는 것이 중요: 선택 B
- 네트워크 프로토콜까지 독립 제품화해야 함: 선택 C

선택 B를 택해도 휴대폰에서는 RoamADB 앱 하나만 사용한다. 달라지는 것은 뒤에서 장치들을 연결해 주는 제어 서버의 소유자다.

## 7. 구현 승인 경계

선택 D/A/B/C가 확정되기 전에는 네트워크 기반 코드를 구현하지 않는다.
